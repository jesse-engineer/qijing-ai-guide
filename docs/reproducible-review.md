# 怎样记录一次可复核的同人创作体验

[返回首页](../README.md) · [模板用法](../templates/README.md)

这份记录表供教程作者、读者和其他创作项目复用。它是一套记录方法，没有预填产品成绩。使用相同的输入也可能得到不同输出，复核的重点是能否看清输入、结果与判断依据。

## 先固定本次范围

| 字段 | 填写内容 |
| --- | --- |
| 日期、产品和入口 | 网页或小程序；记录实际访问日期 |
| 模型或模式 | 界面没有显示时填“未显示”，不推测 |
| 原作与版本 | 如《斗罗大陆》第一部小说；注明资料覆盖范围 |
| 故事时间点 | 具体章节或明确剧情节点；未核实处单独列出 |
| 本次任务 | 讨论脑洞、生成一个场景、局部改写或跨章检查 |
| 用户新增设定 | 列出原创任务、道具与规则，避免与原作混淆 |
| 费用与限制 | 记录实际可见信息；没有测量就不报告成本 |

## 保留四份材料

1. **首次输入**：按原样保留，不能在结果出来后悄悄改成更精确的要求。
2. **首次输出**：保留完整的本次输出；节选时注明省略，记录是否保存成章节。
3. **修改请求**：引用要修改的位置，说明保留什么、改变什么。
4. **修订结果**：与初稿对应比较；保留失败和仍待解决的问题。

若界面让用户先选择时间点、方向或人物关系，也记录这些中间选择。它们会影响结果，不能把多轮协作写成“一句话直接生成”。

## 用证据判断结果

| 观察项 | 判断问题 | 需要的证据 |
| --- | --- | --- |
| 原作边界 | 是否混入其他版本、后期能力或未公开秘密？ | 原作出处与输出位置；无出处则待核实 |
| 视角 | 限知视角是否写入他人不可知的内心？ | 具体句段 |
| 人物行动 | 行动是否有动机和现场信息支撑？ | 对话、行动及上下文；主观判断应标明 |
| 修改范围 | 要求只改对话时，是否改动了其他情节？ | 原稿、修改请求与修订稿逐项对照 |
| 连续性 | 下一场景是否承接时间、位置、道具和知识？ | 至少两个相连场景；仅一场不能判断跨章表现 |
| 保存与管理 | 输出是否确实进入章节或笔记？ | 保存后的界面证据；只出现在聊天中不等于已保存 |

结果使用“本次满足／部分满足／本次未满足／未覆盖”，每项附依据。审美偏好与明确事实错误分开记录，不把“没有检查”算成“通过”。

## 局部修改对照表

| 原稿位置与原句 | 为什么需要修改 | 实际修改请求 | 修订后对应内容 | 是否影响其他内容 |
| --- | --- | --- | --- | --- |
| 待填写 | 事实、视角、连续性或个人偏好 | 按原样记录 | 待填写 | 待核对 |

截图应与对应文字放在一起，只保留本次演示相关区域。发布前检查账户信息、私人项目名称和未授权原作正文是否出现在画面中。

## 写结论时说明范围

可以写：“本次一个场景中，指定的第三人称限知视角得到保留；局部修改后，结尾仍停在同一事件节点。”前提是四份材料确实支持这些判断。

不能仅凭一个场景推断数百章稳定性、所有角色都不 OOC，或一个工具全面优于其他工具。产品方撰写的教程应披露维护者身份；若比较不同产品，应披露每个产品实际使用的提示、轮次、设置及人工介入。
